# TaiYang Multi Image / Audio Loader

一套 ComfyUI 自定义节点，主打两件事：

- **参考素材管理**：在单一节点内管理参考图 / 参考音频，并**自动连线**到下游的多图 / 多音频接入节点
- **图像后处理**：单节点去除人脸高光（只取肤色）；单节点做曝光 / 鲜明度 / 高光 / 阴影 / 色温调整
- 两个后处理节点都**不依赖任何外部节点**，并且自带「原图 / 结果」对比面板

> **前两个节点主要为 MiniMax H3 与 Qwen Image 2.1 服务。**
> 有了它们，给 H3 / Qwen 喂多张参考图（音频）不需要再串一长串加载节点，
> 放好图就会自动接到对应的多图参考槽位上。

| 节点 | 用途 | 数量上限 |
|---|---|---|
| **Multi Image Loader** | 多图参考 + 尺寸缩放 | 最多 16 张 |
| **Multi Audio Loader** | 多音频参考 | 最多 8 个 |
| **面部去高光（只取肤色）** | 单节点去除人脸高光，不依赖外部节点 | 支持批量 |
| **面部去高光（重绘·保纹理）** | 只把高光区送进 SDXL 局部重画，毛孔纹理是重新生成的 | 支持批量 |
| **图片调整** | 13 项：曝光/对比度/高光/阴影/鲜明度/饱和度/色温/色调/色相/清晰度/锐化/暗角/效果强度 + 15 个预设 + 可自存预设 | 支持批量 |
| **图片对比** | 接 A / B 两路图，节点内叠加对比 | 支持批量 |

## 功能

### Node 2.0（Vue 节点）兼容
ComfyUI 1.5x 起提供 **Node 2.0** 渲染模式（设置里的 `Comfy.VueNodes.Enabled`）。
该模式用 Vue 组件画节点，**不再调用画布自绘** `onDrawForeground`——
之前多图 / 多音频节点的界面正是画在画布上的，所以切到 Node 2.0 后会变成一块空白。

现在这两个节点的界面已改成**真实 DOM**（`addDOMWidget`），两种渲染模式都能正常显示：

| 文件 | 作用 |
|---|---|
| `web/js/multi_image_dom.js` | 多图面板：网格缩略图、删除、拖放排序、缩放/对齐/算法/连线目标 |
| `web/js/multi_audio_dom.js` | 多音频面板：行内波形、裁剪竖线、试听、拖放排序、连线目标 |
| `web/js/multi_image.js` / `multi_audio.js` | 业务逻辑（自动连线、输出槽、上传、解码）**只此一份**，DOM 面板 import 复用 |

- 画布自绘代码保留着，但节点挂上 DOM 面板后会自动跳过（`node.__tyDomPanel`），不会出现双份界面
- 面板高度随图片/音频条数自动伸缩，节点不会留一大块空白
- 旧版 LiteGraph 渲染下同样用这套 DOM 界面，两种模式行为一致

**节点输出的推送不能只靠 `node.onExecuted`。** Node 2.0 下前端换成了 `nodeOutputs` +
`onNodeOutputsUpdated` 一套新分发，`onExecuted` 不一定被调用（官方 `PreviewAny` / `Preview3D`
也都是「改 `onExecuted` + 额外挂 `onNodeOutputsUpdated`」双写）。只挂 `onExecuted` 的表现是：
面板一直停在 `properties` 里存的上一次的图，换了图、跑完了也不更新。
现在「面部去高光 / 图片对比 / 图片调整」统一改走 **websocket `executed` 事件**
（`api.addEventListener("executed", …)`，后端每次执行完都会发，带 `display_node` 和 `output`），
`onExecuted` 保留作旧版兼底，两条通道用文件名去重，不会重复解码。

### 多图管理
- 单节点最多 16 张参考图，网格布局（4 列），行数随图片数增长
- 支持上传、删除、**拖拽排序**，也支持**从资源管理器直接拖文件进网格**
- 双击缩略图看大图
- 输出槽数量跟随图片数动态变化：传几张图就显示几个 `image_N`
- 每张图左下角显示**实际送入模型的分辨率**（如 `978 × 1072`），会随缩放/对齐参数实时变

### 尺寸缩放（等价内置 ImageScaleToTotalPixels）
内置了 ComfyUI `Scale Image to Total Pixels` 的能力，省掉再串一个缩放节点。两项参数都**支持填任意数字**：

| 项 | 说明 | 范围 |
|---|---|---|
| 百万像素 | 目标总像素数 ÷ 1024²。`0` = 关闭缩放，保持原分辨率 | 0 ~ 16 |
| 分辨率倍数 | 缩放后的宽高会对齐到该数字的整数倍 | 1 ~ 256（默认 **32**） |
| 插值算法 | `nearest-exact` / `bilinear` / `area` / `bicubic` / `lanczos` | 默认 bilinear |

**操作方式**（两种都行）：
- 点节点底部**缩放条**：左半区改百万像素、右半区改分辨率倍数，弹窗直接输入数字
- 右键菜单：「缩放：输入百万像素」「分辨率倍数：输入数字」「插值算法」「关闭缩放」

**行为说明**：
- 算法与内置节点完全一致：按 `总像素数 = megapixels × 1024²` **等比**缩放，不裁剪、不变形
- 格子里的分辨率实时反映缩放结果（绿色 = 缩放生效，灰色 = 保持原分辨率）
- 缩放只影响送进模型的尺寸，画布预览始终显示原图

### 自动连线（auto_link）
自动把图片按顺序连到下游节点的多图输入槽，支持：

| 目标节点 | 槽位类型 | 示例 |
|---|---|---|
| `TextEncodeQwenImage21` | TemplateNames（1 基） | `images.image_1` |
| `MiniMaxH3ReferenceToVideo` | TemplatePrefix（0 基） | `ref_images.ref_image_0` |
| `MiniMaxH3MaterialPromptStar7` | TemplatePrefix（0 基） | `ref_images.ref_image_0` |
| `TextEncodeQwenImageEditPlus` | 固定槽位（3） | `image1` / `image2` / `image3` |
| `TE_Qwen_Image_2_1_Prompt_Enhancer`<br>（TE MAN Qwen Image 2.1 AI提示词增强） | 固定槽位（8，中文 1 基） | `图片` / `图片2` … `图片8` |

- **自动发现**：扫描画布，任何带 `images` / `ref_images` autogrow 组的节点都会被接入
- **手动指定**：右键菜单可锁定某个节点类型，或指定白名单外的任意节点
- **空槽安全**：没有图的输出返回 `None`，不会把 64×64 黑图当参考图喂给模型
- 目标节点槽位不足时会自动扩展（autogrow）

### 拖拽排序
- 按住图片拖动，松手即换位（DOM 拖放，Node 2.0 下同样可用）
- 松手后顺序落盘，下游连线**自动跟随**（`image_N` 接的是新顺序下第 N 位的图）
- 也可以**从资源管理器直接把图片拖进网格**，落在哪一格就插到哪个位置
- 双击缩略图可看大图

### 多音频加载（Multi Audio Loader）
同包内第二个节点，专门给 **MiniMax H3** 喂参考音频。功能与多图节点一致，只是把图片换成音频。

**能力：**

| 能力 | 说明 |
|---|---|
| 多音频管理 | 单节点最多 **8 个音频**，**上下排列的长条形**布局，波形区长而扁，操作面积大 |
| **区间裁剪** | 每条音频有两条竖线：**左边 = 起始位置**、**右边 = 结束位置**，拖动即可裁剪，只把这一段送进模型 |
| **时间刻度** | 波形下方一条刻度带，**间隔随时长自适应**（2 秒内 0.5 秒一格、5 秒内 1 秒、12 秒内 2 秒、30 秒内 5 秒、90 秒内 10 秒），刻度上的数字带「秒」字；太挤时隔一格标一次 |
| **点击试听** | 点波形从起点播到终点，**再点一次停止**；播放时有黄色播放头 |
| 拖拽排序 | 拖左边的 `⋮⋮` 手柄调顺序，松手后落盘、连线自动跟随 |
| 自动连线 | 自动接到下游多音频参考节点，无需手动连线 |
| 输出槽 | `audio_1` ~ `audio_8`，数量跟随音频数动态变化 |
| 空槽安全 | 没有音频的槽返回 `None`，不会把无效音频喂进模型 |

**裁剪竖线怎么用：**

- 绿线 = 起始位置（可拖到任意位置，但**不会越过结束线**）
- 蓝线 = 结束位置（**只能在起始线右侧**，拖到左边会自动修正）
- 区间外的部分会变暗，区间内高亮；行头显示当前区间，如 `1.5–4.3s`
- 结束线拖到最右边 = 「播放到结尾」
- 波形下方有**刻度带**：间隔随时长自适应（0.5 / 1 / 2 / 5 / 10 秒），数字带「秒」字，
  挤不下时隔一格标一次
- **裁剪后的区间会真正送进模型**（不只是显示）：后端按同样区间切片音频
- 区间会保存进工作流，下次打开依然有效
- 误操作了可以右键「↺ 重置所有裁剪区间」或「✂ 重置某条音频的裁剪区间」

**音频自动连线目标：**

| 目标节点 | 槽位类型 | 示例 |
|---|---|---|
| `MiniMaxH3ReferenceToVideo` | TemplatePrefix（0 基，autogrow 动态槽） | `ref_audios.ref_audio_0` |
| `MiniMaxH3MaterialPromptStar7` | 固定槽位 | `ref_audio_0` / `ref_audio_1` / `ref_audio_2` |

> 自动发现只认 `ref_audios` 组，**不会误连** H3 上的 `ref_video_audios`（那是参考视频的原声）。

**技术细节：**
- 音频经 ComfyUI 的 `/upload/image` 端点上传（唯一通用上传端点），落到 `input/` 目录
- 后端用 `torchaudio` 加载，输出 `{"waveform": ..., "sample_rate": ...}`，与内置 LoadAudio 节点一致
- 试听走 **Web Audio API**：先 `decodeAudioData` 解码，再用 `source.start(0, 起点, 时长)` 按**采样点**播放。
  浏览器对无 Xing 头的 CBR MP3 只能按码率估算 seek 位置（可能差数秒），解码后可完全避免
- 解码后的精确时长会回填给刻度与竖线（`HTMLAudioElement` 的 metadata 对 MP3 只是估算值）
- 波形区显示**真实波形**（由解码数据提取峰值绘制），区间内外一眼可辨
- 非图像类功能（缩放）仅多图节点提供，音频节点不带缩放

### 面部去高光（只取肤色）

**图片 → 本节点 → 去高光图片**，中间不需要接任何其他节点。人脸检测、肤色解析、选高光、取色回填全部在节点内部完成。

链路：

```
LoadImage ──► 面部去高光（只取肤色）──► SaveImage
```

**算法**（等价于 PS 里「通道选高光 + 吸管取周边肤色 + 填充」，但取色只取肤色）：

1. YOLO 找到人脸框 → 只在框内干活，**框外一个像素都不改**
2. Segformer 人脸解析分出 `skin` + `nose` 两类当肤色区
3. RGB 取最大通道当亮度，超过阈值且在脸内 → 高光
4. 取样禁区 = 脸内非皮肤区 ∪ 高光区；在禁区里反复「高斯模糊 → 回填周边纯肤色」，
   让肤色渗进来，`rounds` 轮后得到一张没有高光、只有肤色的底片
5. 底片按羽化后的高光蒙版贴回原图，按 `fill_strength` 混一点原图保住质感

眉毛、眼睛、嘴唇、头发、鼻孔全在取样禁区里，**永远不参与取色**，所以不会出现眉部发黑、唇部发红。

**节点内「原图 / 结果」对比面板：**

节点下半部分自带一块对比区，跑完自动出图，**不用再接任何对比节点**：

- 左半 = 处理前的原图，右半 = 处理后的结果，中间是 **1px 纯黑细线**
- **不用拖、不用按**：鼠标进入面板就直接跟随——X 决定左右分界，Y 决定圆形把手的上下位置
- 圆形把手是**白色圆底 + 左右黑色三角**，贴着分割线走，和常见修图软件的分屏对比一致
- 左上角标「原图」、右上角标「结果」，分割线两侧谁是哪个一目了然
- 图像按等比缩放铺满面板，不变形不裁切；**分割线和把手只在图像范围内活动**，不会伸到上下留白里
- 对比图写在 ComfyUI 的 `temp` 目录，走 `/view?type=temp` 读取，不占 `output`
- 图片引用会存进节点属性，**重新打开工作流上次的对比还在**（temp 被清理过就重跑一次，面板会提示）
- 批量跑时只对比第一张，避免多张图白白占 temp 空间

> 面板高度固定 **440px**，节点默认宽度 **420px**（约 400×400 的图面）；
> 把节点往右拉宽，图会跟着等比放大。

实现方式：用 `addDOMWidget` 塞一块真实 DOM 进节点，而不是在 canvas 上自绘。
**ComfyUI 新旧两种节点渲染（含 Node 2.0 / Vue 节点）都能正常显示**，
在 Node 2.0 下 canvas 自绘的 widget 是不显示的，DOM widget 没这个问题。

**参数：**

| 参数 | 默认 | 说明 |
|---|---|---|
| `highlight_threshold` | 0.80 | **高光阈值，0.30 ~ 1.00。越大 → 选中的高光范围越小**（只压最亮的点） |
| `fill_strength` | 0.80 | 填充强度。0 = 原图不动，1 = 100% 填成周边肤色 |
| `填充明暗` | 0.0 | **填进去那层肤色的明暗**，−1 ~ +1。负 = 更暗（加深立体感），正 = 更亮（避免填完发灰），0 = 严格按周边肤色 |
| `feather` | 10 | 高光区羽化半径，填充块有硬边就加大 |
| `rounds` | 3 | 肤色扩散轮数，填充块里还有残留亮斑就加一轮 |

**两个模型下拉都是实时扫盘的**，往目录里丢模型就会出现在下拉里，不用改代码：

| 用途 | 扫描目录 | 现有模型 |
|---|---|---|
| 人脸检测 | `models/ultralytics/bbox/*.pt` / `*.onnx` | `face_yolov8m.pt` |
| 人脸解析 | `models/RMBG/<含 config.json + preprocessor_config.json 的子目录>/` | `segformer_face` |

**调参口诀：**
- 高光没去干净 → 继续降 `highlight_threshold`（0.80 → 0.75 → 0.70），再考虑调高 `fill_strength`
- 脸整体变哑、没了立体感 → 阈值选区太大，调回 0.85 ~ 0.95
- 填充块有硬边 → 加大 `feather`；填充块里还有亮斑 → 加 `rounds`

**兜底：** YOLO 没检到脸 / 解析模型缺失 / 皮肤区域内没有超过阈值的高光 → 一律原图直出，不会把图搞坏。

**关于「背景上出现灰色方框」：** 早期版本选高光只按「人脸框（矩形）∩ 亮度」判断。
YOLO 给的是矩形框，框里的头发、衣领、背景边缘只要够亮就会被当成高光，
羽化之后填充顶出矩形的四条边，背景上就留下一个灰方块（白发 + 白背景最容易触发）。

现在高光选区多了一道**皮肤掩码**：

```
高光 = 亮度超阈值 ∩ 人脸框 ∩ 皮肤（闭运算填洞 + 外扩 3px）
最终填充范围 = 高光蒙版 ∩ 皮肤软轮廓
```

填充的形状跟着脸的轮廓走，不再是矩形；头发、眼睛、嘴唇、衣领都不再参与填充。

**实测：** 1536×1536 单张首次约 12 ~ 15 秒（含模型加载，之后常驻显存）；
默认 0.80 档改动像素约 14 万（占全图 6%），全部落在人脸框内部，脸外像素级零改动。

> `segformer_face` 需要三个文件：`config.json`、`preprocessor_config.json`、`model.safetensors`，
> 从 hf-mirror 下 323 MB 的 [1038lab/segformer_face](https://hf-mirror.com/1038lab/segformer_face) 放到 `models/RMBG/segformer_face/` 即可。

### 面部去高光（重绘·保纹理）

上面那个是**换色**，这个是**重画**。只把人脸高光那一小块送进 SDXL 局部重绘
（denoise 0.45，结构基本不动），毛孔和皮肤纹理是模型重新生成的，所以叫保纹理。

区别一句话：只取肤色版快、不挑底模，但高光区是「抹平」的；重绘版慢、要底模，
但放大看有真实的皮肤质感。

```
LoadImage
  ├─ YOLO 人脸框 ──────┐
  ├─ segformer 皮肤+鼻子 ┴─ ∩ ─┐
  └─ 亮度 > 阈值 ────────────── ∩ ──► 遮罩 → 外扩 2px / 模糊 4px
                                                  ↓
   VAEEncode → SetLatentNoiseMask → KSampler(dpmpp_2m + karras, cfg 5, denoise 0.45)
                                                  ↓
                            VAEDecode → 按遮罩贴回原图
```

| 参数 | 说明 |
|---|---|
| 高光阈值 | 亮度超过它的**皮肤**像素才算高光。0.75 是原工作流的值；油光大就调低，只想去最亮几点就调高 |
| 底模 | 重绘用的 SDXL checkpoint，默认自动选写实系（名字含 epicrealism / realism） |
| YOLO模型 | 框出人脸，防止重绘跑到脸外 |
| segformer模型 | 分出皮肤+鼻子；眉毛/眼睛/嘴唇/头发不参与，所以不会把五官画花 |
| 种子 | 同图同参数换种子，重绘结果会有细微差别 |
| 步数 | 默认 28；因为 denoise 只有 0.45，实际有效步数约为 步数 × 0.45 |
| 降噪 | 默认 0.45。调高更干净但会丢毛孔、可能把人画成另一个人；调低改不干净 |

- 羽化 4px、遮罩外扩 2px、cfg 5、采样器 dpmpp_2m + karras、正反向提示词全部**按原工作流写死**，
  没有暴露成参数（这些基本不用调，多一个滑杆多一份误调的机会）
- 皮肤上没有高光时直接原图返回，不浪费一次采样
- 首次运行要加载 SDXL 底模（几秒到几十秒，之后常驻），比只取肤色版慢不少
- 同样带「原图 / 结果」对比面板

### 图片调整（13 项 + 15 个预设）

手机修图滑杆 + Photoshop 常用调整，合成一个节点。**不依赖任何模型、无外部节点**，纯 numpy 计算。

```
LoadImage ──► 图片调整 ──► SaveImage
```

参数名全部中文，范围一律 **-100 ~ +100**，0 = 不动，正负对称。

**光调**

| 参数 | 默认 | 作用范围 | 说明 |
|---|---|---|---|
| 曝光 | **+4** | 全图 | 整体明暗，每 100 ≈ ±1 档光 |
| 对比度 | 0 | 全图 | 以中灰为轴向两端撑开，中间调基本不动 |
| 高光 | **+6** | 只碰亮部 | 负数压高光救回死白，正数提亮高光 |
| 阴影 | **-14** | 只碰暗部 | 负数压暗阴影加深层次，正数提亮暗部 |

**色彩**

| 参数 | 默认 | 作用范围 | 说明 |
|---|---|---|---|
| 鲜明度 | **+11** | 低饱和区 + 中间调 | 给灰的地方加饱和、中间调轻微提亮；已经很艳的地方几乎不动（保肤色） |
| 饱和度 | 0 | 全图 | 整体加减彩，拉到 -100 直接黑白 |
| 色温 | **-4** | 全图 | 正数偏暖（加红减蓝），负数偏冷 |
| 色调 | 0 | 全图 | 正数偏品红（减绿），负数偏绿 |
| 色相 | 0 | 全图 | 整体转色相，±100 = ±180° |

**细节 / 效果**

| 参数 | 默认 | 说明 |
|---|---|---|
| 清晰度 | 0 | 中频局部对比，加通透感（相当于 ACR / PS 的清晰度） |
| 锐化 | 0 | 高频 USM，提细节边缘 |
| 暗角 | 0 | 正数压暗四角，负数四角发光 |

**全局**

| 参数 | 默认 | 范围 | 说明 |
|---|---|---|---|
| 效果强度 | **100** | 0 ~ 100 | 前面 12 项的效果整体上几成。100 = 全上，0 = 原图，50 = 效果只上五成 |

效果强度是**最后一步纯混合**，不参与前面任何计算——所以「强度 30%」是「效果只上三成」，
不是把图整体调淡（那是曝光 / 亮度干的事），**也不是输出半透明的 alpha 图**。
想给效果留点余地、不想一眼看出修过，就往下拨它。

> **为什么叫「效果强度」而不是「透明度」**
> 它不改明暗、不动 alpha，只决定前面 12 项的效果上几成。早先叫「透明度」容易让人以为
> 是把画面调半透明，改名之后语义就直白了。旧工作流按位置存参数，改名不影响加载。

> **为什么拨它有时候「看不出变化」**
> 这是数学必然，不是失灵。强度是按比例混合，效果本身越轻，减半后越看不出来：
>
> | 配方 | 效果相对原图 | 强度 100 → 50 的差 |
> |---|---|---|
> | 默认配方（曝光+4/鲜明+11/…） | 平均 3.4 灰阶 | 平均 **1.7** 灰阶 |
> | 青橙电影感 | 8.0 | 4.0 |
> | 悬疑惊悚暗调 | 25.2 | **12.6** |
>
> 人眼对灰阶的分辨下限大约 1~2，所以默认那套轻配方拨强度几乎无感；
> 换成电影 / 类型片那种重效果，拖起来立刻能看出来。
> 面板左上角会实时显示「效果强度 XX%」，轻配方下还会补一句提示——
> 看到角标就说明参数确实在生效。

默认值就是那组常用配方（曝光+4 / 鲜明度+11 / 高光+6 / 阴影-14 / 色温-4，效果强度 100），接上就能直接跑。

**计算顺序：色温 → 色调 → 曝光 → 对比度 → 高光/阴影 → 色相 → 饱和度 → 鲜明度 → 清晰度 → 锐化 → 暗角 → 效果强度。**

顺序本身就是算法的一部分：

- 先白平衡和曝光，后面按亮度加权的步骤才有意义
- 对比度放在高光/阴影之前，否则两端压过之后再拉对比会把细节吃掉
- 色相/饱和度放在细节之前
- 清晰度与锐化**只做亮度细节**，不会把噪点染成彩点
- 暗角永远最后
- 效果强度更是最后一步——它只按比例把「改完的结果」混回原图

高光与阴影都是**按亮度平滑加权**的，只动各自那一段，中间调基本不受影响。

**行为说明：**
- 前 12 项全填 0 且效果强度 100 时**原样返回**，逐像素相等，不做无谓的重采样
- 支持批量：一次喂 N 张就出 N 张
- 支持 RGBA：只改 RGB，alpha 原样保留
- 节点面板是**左边原图 + 右边滑块/数值框 + 顶部预设下拉**，
  拖滑块或直接填数都由前端即时重算重画，不用再点运行（详见下文「图片调整面板」）
- 速度：1536² 单张约 0.2 秒（含清晰度/锐化时略慢），纯 CPU，不占显存

#### 存自己的预设

调出一套喜欢的参数，懒得每次都拨回去，就把它存下来：

1. 在下拉下面那个输入框里写名字（不写也行，会自动叫「我的预设 1 / 2 / …」）
2. 点 **保存** → 当前 12 项参数存进下拉的**「我的预设」**分组，并当场选中它
3. 想删掉哪个，在下拉里选中它，点 **删除**

规则：

- 存的是**前 12 项**（曝光…暗角），**不含效果强度**——跟内置预设一个口径，强度永远是你手上那个总闸
- 名字跟自己存过的重名 → **直接覆盖**那一项，不会堆一堆同名的
- 名字跟内置预设重名 → 拒绝并提示，内置的 15 项不会被顶掉
- **内置预设不能删**，点删除会提示；只有「我的预设」里的能删
- 删除**不改当前参数**，只是把收藏去掉（图不会突然变样）
- 存的参数和某个预设相同时，下拉显示名字；重新打开工作流也认得出来
- 存在浏览器本地（`localStorage`），**跨工作流、跨节点、刷新都在**；换浏览器 / 清站点数据会丢
- 多个 ComfyUI 标签页同时开时，一边存/删，另一边会自动跟着刷新下拉
- 同名不同值的两套不会打架：选中哪套就显示哪套，不会自己跳走

> 提示：存之前先选一下「原图」把参数归零再拨，能避免上一套风格的残留混进来。

#### 图片调整面板

节点宽 680、面板高 462，左边是图，右边是**预设下拉 + 预设名/保存/删除 + 13 行（滑杆 + 数值框）**。
**拖滑杆或直接填数，左边的图当场变**，不需要执行节点。

- **每个参数既能拖、也能填**：右边的数值框可以直接输入（回车或点别处生效），
  填超范围会自动夹回边界，填空 / 只填个负号会回到原值，不会把空串提交给后端
- **强度有实时角标**：把「效果强度」拨到 100 以下，预览左上角会出现「效果强度 XX%」；
  拨到 0 显示「原图 · 效果 0%」。轻配方下角标还会补一句「当前配方本身很轻，强度变化本来就小」，
  省得怀疑参数没生效
- **底图不用等运行**：接上上游（`LoadImage` 之类）就直接把图取过来；上游执行过的图、上次运行缓存的图也能用
- 三条取图来源按可靠度自动兜底：上次运行留在节点里的图 → 上游执行后缓存的图 → 上游节点 widget 里的文件名
- 预览最长边降采样到 720px，拖动时逐帧重算，2 万像素级内核也在 10ms 以内，跟手
- 算法与后端 `image_adjust.py` **同一套系数、同一计算顺序**，所以预览看到的就是出图结果
  （预览是降采样过的，细节锐化的观感会略有出入，以实际出图为准）
- 面板里原生滑块被压成 0 高度隐藏起来，但值仍在、照样序列化，工作流照常保存 / 提交
- 节点从工作流加载（`onConfigure`）时会把存下的参数同步回面板，并按数值反查该显示哪个预设
- 换掉上游的图，底图会跟着换；`temp` 被清理且上游也读不到时，预览显示「重跑一次即可」

### 图片对比

专门用来看「改前 / 改后」的差异，**本身不改图**。

```
LoadImage ──► 图片对比(A)
                   ├──► SaveImage（输出 = B 图原样）
LoadImage ──► 图片对比(B)
```

或者更常见的接法：把去高光 / 图片调整的输出接到 B，原图接到 A，一眼看差多少。

| 输入 | 说明 |
|---|---|
| `image_a` | A 图，显示在面板左半边（角标「A」） |
| `image_b` | B 图，显示在面板右半边（角标「B」），同时是本节点的输出 |

- 输出**直接把 B 递出去**，不接 SaveImage 也不影响对比
- 本节点注册成了**输出节点**（`OUTPUT_NODE = True`），和 `PreviewImage` 一个待遇：
  输出端口空着也会被执行。否则 ComfyUI 只会执行「输出节点 + 它们的上游」，
  这条链子不在执行路径上，面板永远是空白
- `image_a` / `image_b` 都是**可选输入**：忘了接线不会让整条队列报错（输出给一张 8×8 占位图）
- 交互与去高光节点完全一致：**鼠标移进面板就跟随**，X 决定左右分界（1px 黑线），Y 决定圆形把手位置，不用拖
- 两图尺寸不同也能比：**A 会被拉到 B 的显示矩形上**严格对齐（会有一点比例失真），
  面板底部提示尺寸不一致。若不做这步，两张图各按自己的比例居中，线按 B 算、A 偏在别处，扫起来是错位的
- A / B 上游都是 `LoadImage` 这类节点时，**接上线就能看到图**，不用先运行；
  上游是采样 / 处理结果时，得跑一次才有图（前端拿不到文件名）
- `temp` 目录被清理后，坏掉的那张会被自动丢弃并退回空状态提示，不会留个黑框
- 支持批量：只取每批第一张做预览，输出仍按输入的 B 整批透传

**调参口诀：**
- 整体发灰、不够通透 → 鲜明度 +15 ~ +30，不够再加清晰度 +20
- 亮部死白、天空没层次 → 高光 -20 ~ -40
- 暗部糊成一团 → 阴影往上；暗部太脏想加深层次 → 阴影往下
- 画面偏黄 / 偏蓝 → 色温往反方向拨，一次 5 ~ 10 就够
- 肤色发黄发绿 → 色调往正拨一点（+5 ~ +10）
- 想让人物从背景里跳出来 → 暗角 +20 ~ +40，配合清晰度 +20

## 安装

```bash
cd ComfyUI/custom_nodes
git clone https://github.com/winchao110/TaiYang_MultiImage.git
```

重启 ComfyUI 即可。分类 `TaiYang` 下有三个节点：

- **Multi Image Loader** —— 多图参考
- **Multi Audio Loader** —— 多音频参考
- **面部去高光（只取肤色）** —— 去人脸高光

## 使用

### 多图
1. 添加节点 `Multi Image Loader`
2. 点网格里的 `＋` 上传图片（可多选），或者直接把图片文件拖进网格
3. 在画布上放置一个支持多图参考的节点（如 `TextEncodeQwenImage21`）
4. 图片会自动连过去；若没有，用右键菜单的「重新自动连线」
5. 拖缩略图可调顺序，双击看大图，`×` 移除

### 多音频
1. 添加节点 `Multi Audio Loader`
2. 点 `＋ 添加音频` 上传音频（可多选），或者直接把音频文件拖进来
3. 放置 `MiniMaxH3ReferenceToVideo` 或 `MiniMaxH3MaterialPromptStar7`
4. 音频会自动连到 `ref_audio` 槽；拖 `⋮⋮` 手柄可改顺序，连线自动跟随
5. 点波形试听，拖绿 / 蓝竖线裁出要送进模型的那一段

面板底部的下拉就是 `auto_link` 模式，可在「自动 / 关闭 / 指定目标」之间切换。
右键菜单可指定具体目标节点类型。

### 面部去高光
1. 添加节点 `面部去高光（只取肤色）`
2. `LoadImage` 接 `image`，输出接 `SaveImage`
3. 先按默认 `highlight_threshold = 0.80` 跑一张，看效果再决定往上或往下调
4. 跑完后节点下半部分出现 **原图 / 结果 对比面板**，鼠标在面板里移动即可左右、上下跟着扫

### 面部去高光（重绘·保纹理）
1. 添加节点 `面部去高光（重绘·保纹理）`
2. `LoadImage` 接 `image`；`底模` 选一个写实系 SDXL checkpoint
3. 先按默认（阈值 0.75 / 28 步 / 降噪 0.45）跑一张——这就是原工作流的数值
4. 嫌改得不干净就把**降噪**往上拨（0.5 ~ 0.6），嫌脸变了就往下拨（0.35 ~ 0.4）
5. 只想去最亮的高光点、不想动整片油光 → 高光阈值往上调到 0.85 左右

### 图片调整
1. 添加节点 `图片调整`
2. `LoadImage` 接 `image`，输出接 `SaveImage`
3. 13 项默认就是常用配方；想快就直接用右列顶部的预设下拉，选一个风格整套参数就位
4. **接上线就能看**：左边出现原图，拖滑杆或直接在数值框里填数，左边当场出效果——不用点运行，满意了再跑一次出图
5. 觉得效果太猛，把最下面的「效果强度」往下拨（70 ~ 85 通常刚刚好）
6. 想微调就按上面「调参口诀」一项一项拨
7. 调顺了就在下拉下面的输入框写个名字，点**保存**存成自己的预设，下次直接从「我的预设」里选

### 图片对比
1. 添加节点 `图片对比`
2. A 接「改前」的图，B 接「改后」的图（B 也是本节点输出，想存就往后接 `SaveImage`）
3. 鼠标在面板里移动即可左右、上下跟着扫
4. A / B 都接 `LoadImage` 时第 2 步接完就能看；接的是采样 / 处理结果才需要**跑一次**
   （本节点是输出节点，不用在它后面再挂一个 `PreviewImage` 逼它执行）

## 依赖

多图 / 多音频节点 ComfyUI 本身已包含全部依赖，无需额外安装：

- 多图节点：`numpy`、`torch`、`Pillow`、`folder_paths`
- 多音频节点：额外用到 `torchaudio`（ComfyUI 音频功能自带）

**面部去高光**额外依赖三个包（ComfyUI 环境一般都有，缺了才需要装）：

```bash
pip install opencv-python ultralytics transformers
```

以及两个模型文件（见上文「面部去高光」一节）。缺 `ultralytics` / `transformers` 时**不会**导致整个节点包加载失败，
只是这个节点在运行时报错——因为算法模块是延迟导入的。

**面部去高光（重绘·保纹理）** 在上面两个模型之外，还要一个 SDXL checkpoint
（放 `models/checkpoints/`），并且依赖 ComfyUI 自己的 `comfy.sd` / 采样器，
所以**只能在 ComfyUI 里跑**，不能像纯算法版那样脱离环境单独调用。

**图片调整**只用 `numpy`，**不需要任何模型和额外依赖**。

## 旧工作流兼容（参数为空字符串）

**现象**

运行时报：

```
Failed to convert an input value to a INT value: 饱和度, , invalid literal for int() with base 10: ''
```

**原因**

ComfyUI 在真正执行节点之前，会先在 `execution.py` 里做类型校验：`INT` 走 `int(val)`、`FLOAT` 走 `float(val)`。
只要前端送来的是**空字符串**，这一步就抛异常，整个 prompt 直接判为非法，**节点代码根本还没开始跑**。

空字符串来自**旧版本存的工作流**：图片调整节点最早只有 5 个参数，后来扩到 12 个，现在 13 个（多一个效果强度）。
打开旧工作流时，新增的那些参数没有对应存值，widget 的值就是 `""`。

**处理（已内置三层兜底，无需手动操作）**

| 时机 | 行为 |
|---|---|
| 加载工作流（`onConfigure`） | 检测到 `widgets_values` 比当前参数少 → 整组重置为默认值，并打印一行警告 |
| 节点创建 / 单个值为空 | 只把空掉的那几个参数回填默认值，其余不动 |
| 提交前（拦截 `graphToPrompt`） | 逐个数字参数体检：空串、`null`、`NaN`、非数字字符串 → 换默认值；`"11"` 这种字符串数字 → 转真数字。**模型名和连线不动** |

后端节点内部也做了同样的容错（`float("")` / `int("")` 一律回落默认），保证 API 直接调用不会炸。

**建议**：旧工作流里的参数是**按位置错位**存进去的（旧的「色温」会落到新的「鲜明度」上），
兜底只能保证能跑，值对不对没法替你判断。**最干净的做法是把节点删掉重新拖一个**，参数就会回到正确默认值。

## 兼容性

- ComfyUI 1.5x 及以上（前端 autogrow API）
- **Node 2.0（Vue 节点）与旧版 LiteGraph 渲染都支持**：多图 / 多音频的界面是真实 DOM，
  不依赖画布自绘（详见上文「Node 2.0 兼容」）
- 纯前端扩展 + 后端节点，无外部服务依赖
- 节点可正常**折叠**与**手动缩放**，面板高度随内容条数自动伸缩

## 已知限制

- `auto_link` 自动发现模式下，一个 loader 会同时连接画布上**所有**符合条件的节点；
  如需只连某一个，请用右键菜单「指定多图目标」锁定
- Node 2.0 下界面是 DOM 版：拖拽排序**没有**原来那种实时让位动画，松手即换位；
  悬停高亮、尺寸标注等其余信息都在
- 音频波形要等浏览器解码完才出现（大文件约 1 秒），解码前只显示空白波形区，裁剪竖线也要等它
