# TaiYang Multi Image / Audio Loader

一套 ComfyUI 自定义节点包，共 **6 个节点**，做三件事：

- **参考素材管理**：在一个节点里管好参考图 / 参考音频，并**自动连线**到下游的多图 / 多音频接收节点
- **图像后处理**：去人脸高光、调色、把参考图里的杂脸涂掉
- **看图**：节点内直接叠加对比「改前 / 改后」

后处理节点都**不依赖任何外部节点**，拖一个进来接上就能用。

> **GitHub**：<https://github.com/winchao110/TaiYang_MultiImage>
>
> **整合包（模型 + 工作流）**：<https://pan.quark.cn/s/bc37598df71d>
> 节点要用的 SDXL 底模、人脸检测、人脸解析模型和示例工作流都打包在里面，
> 懒得逐个找模型就直接从这里拿。
>
> **前两个节点主要为 MiniMax H3 与 Qwen Image 2.1 服务。**
> 有了它们，给 H3 / Qwen 喂多张参考图（音频）不需要再串一长串加载节点，
> 放好图就会自动接到对应的多图参考槽位上。

## 节点一览

| # | 节点（列表里显示的名字） | 一句话用途 | 需要的模型 |
|---|---|---|---|
| 1 | **多图载入** | 一个节点管 16 张参考图，自动连线到下游多图槽位（可一键关掉改手动） | 无 |
| 2 | **多音频载入** | 一个节点管 8 段参考音频，可拖线裁剪区间 | 无 |
| 3 | **面部去高光（重绘·保纹理）** | 把脸部高光送进 SDXL 局部重画，毛孔是真实的 | SDXL 底模 + 人脸检测 + 人脸解析 |
| 4 | **小脸涂抹（去参考图杂脸）** | 把主视图之外的小脸整片涂成纯色 | 人脸检测 |
| 5 | **图片调整** | 13 项调色 + 15 个预设 + 可自存预设 | 无 |
| 6 | **图片对比** | 接 A / B 两路图，节点内叠加对比 | 无 |
| 7 | **模型计算FP16** | 非量化权重统一到 FP16（int8/int4 保持存储、前向反量化），H3 在 FP16 下的三处数值保护 | MiniMax H3 主模型 |
| 8 | **显存分块加载** | 沿 token 维切分注意力 / 位置编码 / 前馈的临时激活峰值，削长序列显存 | MiniMax H3 主模型 |
| 9 | **图片保存** | 一个预览区搞定「存上游、载本地、删图、往下传」 | 无 |

> 早先还有一个「面部去高光（只取肤色）」纯算法节点，已从节点列表移除。
> 它的算法模块 `face_dehighlight.py` 仍然保留 —— 节点 3 的人脸框和皮肤掩码正是靠它。

> **节点 7 / 8 与显存编译图**：这两个节点会在每个 block 内部动态申请临时显存（FP32 残差、
> 逐层反量化权重、分块缓冲），和 ComfyUI 0.43 的 aimdo 逐块预编译分配计划本质冲突，
> 不处理的话第二遍采样会抛 `aimdo memory compile error`。所以只要它们有一个开着，
> 本包会在运行时打开 `--disable-comfy-compiler`（只停显存分配计划，动态显存加载 /
> 权重流式加载 / 预取队列全部保留）；两个都关掉自动恢复。两者都不绑定显卡型号。

## 1. 多图载入（Multi Image Loader）

### 用途

给多图参考类节点（Qwen Image 2.1 / MiniMax H3 等）一次性准备好最多 **16 张**参考图，
并在接入下游时**自动按顺序连线**，省掉十几个 `LoadImage` + 手动拖线的活。

### 实现方法

- **界面**：用 `addDOMWidget` 把一块**真实 DOM** 塞进节点（网格缩略图 + 上传 + 删除 + 拖放排序），
  不是画在 canvas 上。所以 Node 2.0（Vue 节点）和旧版 LiteGraph 两种渲染都正常显示
- **业务逻辑**：`web/js/multi_image.js` 只管自动连线、输出槽、上传、解码；
  `web/js/multi_image_dom.js` 只负责界面。逻辑**只有一份**，两个文件互相 import 复用
- **缩略图完整显示**：格子里用 `object-fit: contain`，竖图 / 宽图都整张看得见，
  不会被裁成正方形（画布自绘模式同样按 contain 绘制，并给底部尺寸条让位）
- **缩放**：内置 ComfyUI `Scale Image to Total Pixels` 的那套算法（按总像素数等比缩放，
  宽高再对齐到指定步长），不裁剪、不变形
- **自动连线**：扫描画布上带 `images` / `ref_images` autogrow 组的节点，
  按各自的槽位命名规则把 `image_N` 接进去
- **自动连线开关**：面板顶部（右上「清空」左边）有个开关，默认**开启**。
  点一下变「开启自动连线」，同时把本节点已经连出去的线全部断开，之后完全由你手动拉线；
  关闭期间加图 / 删图 / 排序 / 换工作流都不会再动线（手拉的线原样留着）。
  再点一下恢复自动连线，按当前图片重新接回下游。状态存在 `auto_link` 里，随工作流存档
- **载入期保护**：切标签页 / 打开别的工作流时，前端会用 `loadGraphData` 把整张图**拆掉重建**。
  重建期间本节点**绝不建链**（`beforeConfigureGraph` 打标记、`afterConfigureGraph` 才收口），
  否则会和随后恢复的存档连线叠成「同一个槽两条线」。
  收口时执行一条硬性规则：**输出序号必须等于槽位序号**，对不上的（孤儿、错位的、输出槽已不存在的）一律清掉，
  缺的槽自动补齐；收口跑四轮（50ms / 310ms / 1.2s / 3.4s），所以 `autogrow` 后来才扩出来的槽也能覆盖到
- **排查入口**：控制台执行 `__tyAuditImageLinks()` 会打印本节点到各目标的全部连线
  （`out序号 → [槽下标] 槽名 序号=…`，错位的行会标「← 错位」）
- **空槽**：没有图的输出槽返回 `None`，不会把 64×64 黑图当参考图喂给模型

### 用法

1. 添加节点 `多图载入`
2. 点网格里的 `＋` 上传图片（可多选），或者**直接从资源管理器把文件拖进网格**
3. 在画布上放一个支持多图参考的节点（如 `TextEncodeQwenImage21`）
4. 图片会自动连过去；没连上就用右键菜单「重新自动连线」
   不想让它自动连，就点面板顶部那个「关闭自动连线」开关（断开已连的线，改手动）
5. 拖缩略图可调顺序，双击看大图，`×` 移除

**管理细节：**

- 单节点最多 16 张，网格布局（4 列），行数随图片数增长
- 输出槽数量跟随图片数动态变化：传几张图就显示几个 `image_N`
- 每张图左下角显示**实际送入模型的分辨率**（如 `978 × 1072`），随缩放/对齐参数实时变
- 支持上传、删除、**拖拽排序**，也能**从资源管理器直接拖文件进网格**（落在哪一格就插到哪个位置）
- 松手后顺序落盘，下游连线**自动跟随**（`image_N` 接的是新顺序下第 N 位的图）

**尺寸缩放**（等价内置 `ImageScaleToTotalPixels`）：

| 项 | 说明 | 范围 |
|---|---|---|
| 百万像素 | 目标总像素数 ÷ 1024²。`0` = 关闭缩放，保持原分辨率 | 0 ~ 16 |
| 分辨率倍数 | 缩放后的宽高会对齐到该数字的整数倍 | 1 ~ 256（默认 **32**） |
| 插值算法 | `nearest-exact` / `bilinear` / `area` / `bicubic` / `lanczos` | 默认 bilinear |

- 两种改法：点节点底部**缩放条**（左半区改百万像素、右半区改分辨率倍数，弹窗直接输入数字），
  或者右键菜单「缩放：输入百万像素」「分辨率倍数：输入数字」「插值算法」「关闭缩放」
- 算法与内置节点完全一致：按 `总像素数 = megapixels × 1024²` **等比**缩放，不裁剪、不变形
- 格子里的分辨率实时反映缩放结果（绿色 = 缩放生效，灰色 = 保持原分辨率）
- 缩放只影响送进模型的尺寸，画布预览始终显示原图

**自动连线（auto_link）支持的目标：**

| 目标节点 | 槽位类型 | 示例 |
|---|---|---|
| `TextEncodeQwenImage21` | TemplateNames（1 基） | `images.image_1` |
| `MiniMaxH3ReferenceToVideo` | TemplatePrefix（0 基） | `ref_images.ref_image_0` |
| `MiniMaxH3MaterialPromptStar7` | TemplatePrefix（0 基） | `ref_images.ref_image_0` |
| `TextEncodeQwenImageEditPlus` | 固定槽位（3） | `image1` / `image2` / `image3` |
| `TE_Qwen_Image_2_1_Prompt_Enhancer`<br>（TE MAN Qwen Image 2.1 AI提示词增强） | 固定槽位（8，中文 1 基） | `图片` / `图片2` … `图片8` |

- **自动发现**：扫描画布，任何带 `images` / `ref_images` autogrow 组的节点都会被接入
- **手动指定**：右键菜单可锁定某个节点类型，或指定白名单外的任意节点
- 目标节点槽位不足时会自动扩展（autogrow）

**槽位扩展为什么不自己造（踩过的坑，别再改回去）：**

ComfyUI 前端 1.55 起把「哪条连线接在哪个槽上」搬进了 graph 内部索引
（`slotLinks.ts` 的 `inputLink` / `inputLinkId` / `outputHasLinks`），
`node.inputs` 只剩一个 legacy 视图。前端自己的扩槽函数 `addAutogrowGroup`
是靠 `commitMutatedInputs → replaceNodeInputs` 把这套索引整体重建一遍才落地的。

早期版本这里用 `node.inputs.splice()` 手工塞槽位，只动了数组、没重建索引，后果是连锁的：

1. graph 认为这些槽「没连接」→ `connectSlots` 里查不到要替换的旧线 → 直接追加新线；
2. 一个输入槽上叠出多条 link，`inputs[slot].link` 只显示最后一条，其余全变孤儿；
3. 孤儿照样存进工作流 JSON；
4. 重开工作流时前端照着 `graph.links` 画线 —— 所有孤儿都画在 `ref_image_0` 上，
   看起来就是「好几张图全连到参考图 1」的连错线。

现在的做法：**不造槽**，按 0、1、2… 顺序连线，每连上「本组最后一个槽」，
前端 `onConnectionsChange → autogrowInputConnected` 会同步补出下一个槽。
若最后一个槽本来就连着正确的线（同源跳过，扩张不会被触发），
就把这条线**断开原样接回**一次把扩张唤醒。

另外每次同步都会做一次体检：同一槽位上挂了多条 link 的，只留一条
（优先留输出序号与槽序号对得上的那条），其余硬删。所以**已经被存坏的工作流，
重开一次就自动修好**，控制台会出现「清理了 N 条残留连线」。

### 需要的模型

**无。** 只用 ComfyUI 自带的 `numpy`、`torch`、`Pillow`、`folder_paths`。

## 2. 多音频载入（Multi Audio Loader）

### 用途

专门给 **MiniMax H3** 喂参考音频。功能与多图节点对应，只是把图片换成音频，
并且多了**区间裁剪**——只把音频里需要的那一段送进模型。

### 实现方法

- **界面**：同样是 `addDOMWidget` 的真实 DOM 面板，上下排列的**长条形**布局，波形区长而扁
- **波形**：不是用 `<audio>` 的 metadata 估算，而是用 **Web Audio API** `decodeAudioData`
  解码后从采样数据里提取峰值来画，所以是**真实波形**（区间内外一眼可辨）
- **试听**：解码后用 `source.start(0, 起点, 时长)` 按**采样点**播放。
  浏览器对无 Xing 头的 CBR MP3 只能按码率估算 seek 位置（可能差数秒），解码后完全避免这个问题
- **时长**：解码后的精确时长会回填给刻度与竖线（`HTMLAudioElement` 的 metadata 对 MP3 只是估算值）
- **裁剪落盘**：区间会保存进工作流，**后端按同样区间真正切片**音频后再送模型（不只是显示）
- **上传**：音频走 ComfyUI 的 `/upload/image` 端点（唯一通用上传端点），落到 `input/` 目录
- **加载**：后端用 `torchaudio`，输出 `{"waveform": …, "sample_rate": …}`，与内置 `LoadAudio` 一致
- **自动连线**：与多图载入同一套逻辑（`ref_audios` 等 autogrow 组 + 固定槽位节点），
  同样有**载入期保护**（切工作流时重建过程中不建链，载入结束再按「输出序号 = 槽位序号」收口）

### 用法

1. 添加节点 `多音频载入`
2. 点 `＋ 添加音频` 上传音频（可多选），或者直接把音频文件拖进来
3. 放置 `MiniMaxH3ReferenceToVideo` 或 `MiniMaxH3MaterialPromptStar7`
4. 音频会自动连到 `ref_audio` 槽；拖 `⋮⋮` 手柄可改顺序，连线自动跟随
5. 点波形试听，拖绿 / 蓝竖线裁出要送进模型的那一段

**能力：**

| 能力 | 说明 |
|---|---|
| 多音频管理 | 单节点最多 **8 个音频**，上下排列的长条形布局 |
| **区间裁剪** | 每条音频两条竖线：**左边 = 起始**、**右边 = 结束**，拖动即裁剪 |
| **时间刻度** | 波形下方刻度带，**间隔随时长自适应**（2 秒内 0.5 秒一格、5 秒内 1 秒、12 秒内 2 秒、30 秒内 5 秒、90 秒内 10 秒），数字带「秒」字；太挤时隔一格标一次 |
| **点击试听** | 点波形从起点播到终点，**再点一次停止**；播放时有黄色播放头 |
| 拖拽排序 | 拖左边的 `⋮⋮` 手柄调顺序，松手后落盘、连线自动跟随 |
| 自动连线 | 自动接到下游多音频参考节点，无需手动连线 |
| 输出槽 | `audio_1` ~ `audio_8`，数量跟随音频数动态变化 |
| 空槽安全 | 没有音频的槽返回 `None` |

**裁剪竖线怎么用：**

- 绿线 = 起始位置（可拖到任意位置，但**不会越过结束线**）
- 蓝线 = 结束位置（**只能在起始线右侧**，拖到左边会自动修正）
- 区间外变暗、区间内高亮；行头显示当前区间，如 `1.5–4.3s`
- 结束线拖到最右边 = 「播放到结尾」
- 区间会保存进工作流，下次打开依然有效
- 误操作了可以右键「↺ 重置所有裁剪区间」或「✂ 重置某条音频的裁剪区间」

**音频自动连线目标：**

| 目标节点 | 槽位类型 | 示例 |
|---|---|---|
| `MiniMaxH3ReferenceToVideo` | TemplatePrefix（0 基，autogrow 动态槽） | `ref_audios.ref_audio_0` |
| `MiniMaxH3MaterialPromptStar7` | 固定槽位 | `ref_audio_0` / `ref_audio_1` / `ref_audio_2` |

> 自动发现只认 `ref_audios` 组，**不会误连** H3 上的 `ref_video_audios`（那是参考视频的原声）。

面板底部的下拉就是 `auto_link` 模式，可在「自动 / 关闭 / 指定目标」之间切换；
右键菜单可指定具体目标节点类型。非图像类功能（缩放）仅多图节点提供。

### 需要的模型

**无。** 额外只用到 `torchaudio`（ComfyUI 音频功能自带）。

## 3. 面部去高光（重绘·保纹理）

### 用途

人脸上一片油光（额头、鼻梁、鼻头、两颊）过曝发白、丢了皮肤质感。
本节点把**高光那一小块**送进 SDXL 局部重画，毛孔和皮肤纹理是模型**重新生成**的，
所以叫「保纹理」。结构基本不动（denoise 0.45 保留原结构），改完还是同一个人。

### 实现方法

```
LoadImage
  ├─ YOLO 人脸框 ──────┐
  ├─ segformer 皮肤+鼻子 ┴─ ∩ ─┐
  └─ 亮度 > 阈值 ────────────── ∩ ──► 遮罩 → 外扩 2px / 模糊 4px
                                                  ↓
   VAEEncode → SetLatentNoiseMask → KSampler(dpmpp_2m + karras, cfg 5, denoise 0.45)
                                                  ↓
                            VAEDecode → 按遮罩贴回原图
```

- 高光选区 = **人脸框 ∩ 皮肤（含鼻子）∩ 亮度超阈值**。眉毛、眼睛、嘴唇、头发全被排除，
  所以不会把五官画花，也不会在背景上留下灰方块
- 只把遮罩内那一小块喂进采样器，不是整张图重绘
- 羽化 4px、遮罩外扩 2px、cfg 5、采样器 `dpmpp_2m + karras`、正反向提示词全部**按原工作流写死**，
  没有暴露成参数（这些基本不用调，多一个滑杆多一份误调的机会）
- 遮罩为空（皮肤上没有高光）时**直接原图返回**，不浪费一次采样

### 用法

1. 添加节点 `面部去高光（重绘·保纹理）`
2. `LoadImage` 接 `image`；`底模` 选一个写实系 SDXL checkpoint
3. 先按默认（阈值 0.75 / 28 步 / 降噪 0.45）跑一张——这就是原工作流的数值
4. 嫌改得不干净 → **降噪**往上拨（0.5 ~ 0.6）；嫌脸变了 → 往下拨（0.35 ~ 0.4）
5. 只想去最亮的高光点、不想动整片油光 → 高光阈值上调到 0.85 左右
6. 跑完在面板里出现「原图 / 结果」叠加对比，鼠标移进去就跟随，不用拖

| 参数 | 默认 | 说明 |
|---|---|---|
| 高光阈值 | 0.75 | 亮度超过它的**皮肤**像素才算高光。油光大就调低，只想去最亮几点就调高 |
| 底模 | 自动选写实系 | 重绘用的 SDXL checkpoint，名称含 epicrealism / realism 的排最前 |
| YOLO模型 | `face_yolov8m.pt` | 框出人脸，防止重绘跑到脸外 |
| segformer模型 | `segformer_face` | 分出皮肤 + 鼻子；眉毛/眼睛/嘴唇/头发不参与 |
| 种子 | 123456789 | 同图同参数换种子，重绘结果会有细微差别（批量时自动 +i） |
| 步数 | 28 | 因为 denoise 只有 0.45，实际有效步数约为 步数 × 0.45 |
| 降噪 | 0.45 | 调高更干净但会丢毛孔、可能把人画成另一个人；调低改不干净 |

- 首次运行要加载 SDXL 底模（几秒到几十秒，之后常驻显存）
- 支持批量，每张换一个种子，免得几张重绘得一模一样

### 需要的模型

| 用途 | 放哪 | 文件名 | 大小 |
|---|---|---|---|
| SDXL 底模 | `models/checkpoints/` | 任意写实系 SDXL，如 `XL-epicrealismXL_vxviLastfameRealism.safetensors` | 数 GB |

## 4. 小脸涂抹（去参考图杂脸）

### 用途

多视角人像参考图里常常同时摆着「一张主视图大脸 + 若干张正面 / 侧面小脸」。
整张图直接喂给大模型，小脸会把注意力分走，主脸反倒还原不准。
本节点把**主视图之外的所有人脸整片涂成纯色**，身体、头发、衣服一律不动。

### 实现方法

1. YOLO 检出**全部**人脸，阈值放宽到 0.12（实测纯侧脸 conf 0.81，能检出）
2. 按框面积降序排序，前 `保留脸数` 张算主脸保留，其余全算小脸
3. 小脸框**居中放大 1.8 倍**，画圆角矩形（圆角 25%），再高斯羽化 2px，不做硬直角切边
4. 按遮罩把原图与填充色混合，得到结果图

**为什么按面积判主脸，而不是按位置：** 实测同一张 1664×960 的素材，
`face_yolov8m` 在 conf 0.10 下检出 3 张脸：

| 位置 | 占画面面积 | conf | 判定 |
|---|---|---|---|
| 左侧主视图 | 4.07% | 0.90 | 主脸（保留） |
| 右上正面 | 0.40% | 0.83 | 小脸（涂掉） |
| 右上侧面 | 0.29% | 0.81 | 小脸（涂掉） |

主脸面积是小脸的 **10 倍**，面积比这个判据非常干净，
所以素材里小脸摆在右上、中上还是左侧都无所谓，不用管位置。

**为什么涂抹倍数默认 1.8：** YOLO 对纯侧脸框得偏窄（实测侧脸框 54px 宽，正面框 72px），
框的中心又偏向脑后，鼻子和嘴会露在框外。实测扫描：

| 倍数 | 覆盖 | 侧面小脸 |
|---|---|---|
| 1.15 | 0.90% | 鼻子、嘴露在框外 |
| 1.5 | 1.51% | 嘴角还露一点 |
| **1.8** | **2.15%** | **鼻嘴眼全盖住，头发基本还在** |
| 2.2 | 3.22% | 开始吃头发 |

**为什么不按背景色差抠图：** 白背景 + 白水手服这类素材，衣服和白背景的色差小于阈值，
按色差抹会留下一层白色衣服的鬼影（实测过：小人抹掉了，白衣白靴还在）。
本节点只涂人脸框那一块，压根不碰身体，所以不存在这个问题。

全流程纯 CV，**不加载任何大模型**，单张 1 秒内出结果。

### 用法

1. 添加节点 `小脸涂抹（去参考图杂脸）`
2. `LoadImage` 接 `image`，输出接到参考图输入端（或先接 `图片对比` / `SaveImage` 看效果）
3. 默认参数（阈值 0.12 / 保留 1 张 / 倍数 1.8 / 自动背景）就是实测调好的值，先直接跑一张
4. **侧面小脸露了鼻子或嘴** → 涂抹倍数加到 2.0 ~ 2.2
5. **头部以外的部位被涂了** → 检测阈值调高（0.2 ~ 0.3），通常是误检
6. **该涂的没涂** → 检测阈值往下调（0.08 ~ 0.10），没检出小脸就不会涂
7. 想同时保留两张最大的脸（比如主视图 + 一张细节视图）→ 保留脸数改 2

| 参数 | 默认 | 说明 |
|---|---|---|
| `image` | — | 参考图，批量时逐张处理 |
| 人脸模型 | `face_yolov8m.pt` | 位于 `models/ultralytics/bbox/` |
| 检测阈值 | 0.12 | 放低才能检出纯侧脸；误涂就调高 |
| 保留脸数 | 1 | 按面积从大到小保留前几张不涂。`0` = 全涂 |
| 涂抹倍数 | 1.8 | 小脸框居中放大倍数 |
| 填充色 | 自动背景 | 自动取画布四边像素中位色；也可选纯白 / 纯黑 / 中灰 |

- 输出 `image`（涂好的图）+ `mask`（涂抹区域 0~1 软遮罩，可直接当 inpainting 遮罩）
- 一张脸都没检出、或检出的脸数 ≤ 保留脸数时，**原图原样返回**，不报错
- 模型路径不存在时打印提示并原图返回，不会让队列崩
- 运行完在面板里显示「原图 / 涂抹后」对比，和节点 3 共用一个面板

### 需要的模型

| 用途 | 放哪 | 文件名 |
|---|---|---|
| 人脸检测 | `models/ultralytics/bbox/` | `face_yolov8m.pt`（和节点 3 共用同一个） |

额外 Python 包：`opencv-python`、`ultralytics`。**不需要 SDXL、不需要任何大模型。**

## 5. 图片调整

### 用途

把手机修图 App 的那排滑杆和 Photoshop 常用调整合成一个节点：曝光 / 对比度 / 高光 / 阴影 /
鲜明度 / 饱和度 / 色温 / 色调 / 色相 / 清晰度 / 锐化 / 暗角 / 效果强度，共 13 项，
外加 15 个成套预设。**不依赖任何模型、无外部节点。**

```
LoadImage ──► 图片调整 ──► SaveImage
```

### 实现方法

纯 numpy 逐像素计算，参数名全中文，范围一律 **-100 ~ +100**，0 = 不动，正负对称。

**计算顺序本身就是算法的一部分：**

```
色温 → 色调 → 曝光 → 对比度 → 高光/阴影 → 色相 → 饱和度 → 鲜明度 → 清晰度 → 锐化 → 暗角 → 效果强度
```

- 先做白平衡和曝光，后面按亮度加权的步骤才有意义
- 对比度放在高光/阴影之前，否则两端压过之后再拉对比会把细节吃掉
- 清晰度与锐化**只做亮度细节**，不会把噪点染成彩点
- 高光与阴影都是**按亮度平滑加权**的，只动各自那一段，中间调基本不受影响
- 效果强度是**最后一步纯混合**，不参与前面任何计算

**性能**：1536² 单张约 0.2 秒（含清晰度/锐化时略慢），纯 CPU，不占显存。

**行为：**
- 前 12 项全填 0 且效果强度 100 时**原样返回**，逐像素相等，不做无谓的重采样
- 支持批量：一次喂 N 张就出 N 张
- 支持 RGBA：只改 RGB，alpha 原样保留

**光调**

| 参数 | 默认 | 作用范围 | 说明 |
|---|---|---|---|
| 曝光 | **+4** | 全图 | 整体明暗，每 100 ≈ ±1 档光 |
| 对比度 | 0 | 全图 | 以中灰为轴向两端撑开，中间调基本不动 |
| 高光 | **+6** | 只碰亮部 | 负数压高光救回死白，正数提亮高光 |
| 阴影 | **-14** | 只碰暗部 | 负数压暗阴影加深层次，正数提亮暗部 |

**色彩**

| 参数 | 默认 | 作用范围 | 说明 |
|---|---|---|---|
| 鲜明度 | **+11** | 低饱和区 + 中间调 | 给灰的地方加饱和、中间调轻微提亮；已经很艳的地方几乎不动（保肤色） |
| 饱和度 | 0 | 全图 | 整体加减彩，拉到 -100 直接黑白 |
| 色温 | **-4** | 全图 | 正数偏暖（加红减蓝），负数偏冷 |
| 色调 | 0 | 全图 | 正数偏品红（减绿），负数偏绿 |
| 色相 | 0 | 全图 | 整体转色相，±100 = ±180° |

**细节 / 效果**

| 参数 | 默认 | 说明 |
|---|---|---|
| 清晰度 | 0 | 中频局部对比，加通透感（相当于 ACR / PS 的清晰度） |
| 锐化 | 0 | 高频 USM，提细节边缘 |
| 暗角 | 0 | 正数压暗四角，负数四角发光 |

**全局**

| 参数 | 默认 | 范围 | 说明 |
|---|---|---|---|
| 效果强度 | **100** | 0 ~ 100 | 前面 12 项的效果整体上几成。100 = 全上，0 = 原图，50 = 效果只上五成 |

> **为什么叫「效果强度」而不是「透明度」**
> 它不改明暗、不动 alpha，只决定前面 12 项的效果上几成。早先叫「透明度」容易让人以为
> 是把画面调半透明，改名之后语义就直白了。旧工作流按位置存参数，改名不影响加载。

> **为什么拨它有时候「看不出变化」**
> 这是数学必然，不是失灵。强度是按比例混合，效果本身越轻，减半后越看不出来：
>
> | 配方 | 效果相对原图 | 强度 100 → 50 的差 |
> |---|---|---|
> | 默认配方（曝光+4/鲜明+11/…） | 平均 3.4 灰阶 | 平均 **1.7** 灰阶 |
> | 青橙电影感 | 8.0 | 4.0 |
> | 悬疑惊悚暗调 | 25.2 | **12.6** |
>
> 人眼对灰阶的分辨下限大约 1~2，所以默认那套轻配方拨强度几乎无感；
> 换成电影 / 类型片那种重效果，拖起来立刻能看出来。
> 面板左上角会实时显示「效果强度 XX%」，轻配方下还会补一句提示。

默认值就是那组常用配方（曝光+4 / 鲜明度+11 / 高光+6 / 阴影-14 / 色温-4，效果强度 100），接上就能直接跑。

- **底图不用等运行**：接上上游（`LoadImage` 之类）就直接把图取过来；
  三条取图来源按可靠度自动兜底：上次运行留在节点里的图 → 上游执行后缓存的图 → 上游节点 widget 里的文件名
- **预览分辨率可选**：图上方有个下拉，`512p / 720p / 1080p / 1440p`（按**最长边**算，默认 **720**，
  太高的档位在 4K 图上会卡）。选了会记在浏览器里，下次打开还是这个
- 拖动时自动降到档位的 55%（不低于 512）逐帧重算，手一停 160ms 再补一帧满档，
  所以既跟手又清晰：720 档拖动 12.4ms/帧、停手补帧 47ms；1080 档约 2.2 倍耗时
- 换档位直接从已解码的位图重采样，不会重新下载图片；原图本身比档位小就不缩放
- 两档画在同一块画布上（主画布始终是满档尺寸，小图放大用 GPU 采样），切换时不闪、尺寸不跳
- 算法与后端 `image_adjust.py` **同一套系数、同一计算顺序**，预览看到的就是出图结果
  （预览是降采样过的，细节锐化的观感会略有出入，以实际出图为准）
- 面板里原生滑块被压成 0 高度隐藏起来，但值仍在、照样序列化，工作流照常保存 / 提交
- 节点从工作流加载（`onConfigure`）时会把存下的参数同步回面板，并按数值反查该显示哪个预设
- 换掉上游的图，底图会跟着换；`temp` 被清理且上游也读不到时，预览显示「重跑一次即可」

### 需要的模型

**无。** 只用 `numpy`，不需要任何模型和额外依赖。

## 6. 图片对比

### 用途

专门用来看「改前 / 改后」的差异，**本身不改图**。

```
LoadImage ──► 图片对比(A)
                   ├──► SaveImage（输出 = B 图原样）
LoadImage ──► 图片对比(B)
```

更常见的接法：把去高光 / 图片调整 / 小脸涂抹的输出接到 B，原图接到 A，一眼看差多少。

### 实现方法

- 一块 DOM 叠加面板：B 图铺满整块，A 图用 `clip-path` 裁出左半边盖在上面，
  分割线是 1px 黑线，圆形把手是白底 + 左右黑三角
- **本节点注册成了输出节点**（`OUTPUT_NODE = True`），和 `PreviewImage` 一个待遇：
  输出端口空着也会被执行。否则 ComfyUI 只会执行「输出节点 + 它们的上游」，
  这条链子不在执行路径上，面板永远是空白
- 两图尺寸不同也能比：**A 被显式摆到 B 的显示矩形上**严格对齐（会有一点比例失真），
  面板底部提示尺寸不一致。若不做这步，两张图各按自己的比例居中，线按 B 算、A 偏在别处，扫起来是错位的
- `image_a` / `image_b` 都是**可选输入**：忘了接线不会让整条队列报错（输出给一张 8×8 占位图）
- 图片加载失败（`temp` 被清理）会被记进黑名单跳过，退回空状态提示，不会留个黑框

### 用法

1. 添加节点 `图片对比`
2. A 接「改前」的图，B 接「改后」的图（B 也是本节点输出，想存就往后接 `SaveImage`）
3. 鼠标在面板里移动即可左右、上下跟着扫——**不用拖、不用按**
4. A / B 都接 `LoadImage` 时第 2 步接完就能看；接的是采样 / 处理结果才需要**跑一次**
   （本节点是输出节点，不用在它后面再挂一个 `PreviewImage` 逼它执行）

| 输入 | 说明 |
|---|---|
| `image_a` | A 图，显示在面板左半边（角标「A」） |
| `image_b` | B 图，显示在面板右半边（角标「B」），同时是本节点的输出 |

- 支持批量：只取每批第一张做预览，输出仍按输入的 B 整批透传

**调参口诀（图片调整配套）：**
- 整体发灰、不够通透 → 鲜明度 +15 ~ +30，不够再加清晰度 +20
- 亮部死白、天空没层次 → 高光 -20 ~ -40
- 暗部糊成一团 → 阴影往上；暗部太脏想加深层次 → 阴影往下
- 画面偏黄 / 偏蓝 → 色温往反方向拨，一次 5 ~ 10 就够
- 肤色发黄发绿 → 色调往正拨一点（+5 ~ +10）
- 想让人物从背景里跳出来 → 暗角 +20 ~ +40，配合清晰度 +20

### 需要的模型

**无。**

## 通用机制

### Node 2.0（Vue 节点）兼容

ComfyUI 1.5x 起提供 **Node 2.0** 渲染模式（设置里 `Comfy.VueNodes.Enabled`）。
该模式用 Vue 组件画节点，**不再调用画布自绘** `onDrawForeground`——
早先多图 / 多音频的界面正是画在画布上的，切到 Node 2.0 后会变成一块空白。

现在这些界面全是**真实 DOM**（`addDOMWidget`），两种渲染模式都能正常显示：

| 文件 | 作用 |
|---|---|
| `web/js/multi_image_dom.js` | 多图面板：网格缩略图、删除、拖放排序、缩放/对齐/算法/连线目标 |
| `web/js/multi_audio_dom.js` | 多音频面板：行内波形、裁剪竖线、试听、拖放排序、连线目标 |
| `web/js/face_dehighlight_compare.js` | 叠加对比面板（去高光 / 图片对比 / 小脸涂抹共用）+ 数字参数兜底 |
| `web/js/image_adjust_panel.js` | 图片调整的左右分栏面板 |
| `web/js/multi_image.js` / `multi_audio.js` | 业务逻辑（自动连线、输出槽、上传、解码）**只此一份**，DOM 面板 import 复用 |

- 画布自绘代码保留着，但节点挂上 DOM 面板后会自动跳过（`node.__tyDomPanel`），不会出现双份界面
- 面板高度随图片/音频条数自动伸缩，节点不会留一大块空白
- 旧版 LiteGraph 渲染下同样用这套 DOM 界面，两种模式行为一致
- 节点可正常**折叠**与**手动缩放**

### 输出推送（`executed` 事件）

**节点输出的推送不能只靠 `node.onExecuted`。** Node 2.0 下前端换成了 `nodeOutputs` +
`onNodeOutputsUpdated` 一套新分发，`onExecuted` 不一定被调用（官方 `PreviewAny` / `Preview3D`
也都是「改 `onExecuted` + 额外挂 `onNodeOutputsUpdated`」双写）。只挂 `onExecuted` 的表现是：
面板一直停在 `properties` 里存的上一次的图，换了图、跑完了也不更新。

现在统一改走 **websocket `executed` 事件**（`api.addEventListener("executed", …)`，
后端每次执行完都会发，带 `display_node` 和 `output`），`onExecuted` 保留作旧版兼底，
两条通道用文件名去重，不会重复解码。

### 旧工作流兼容（参数为空字符串）

**现象**：运行时报

```
Failed to convert an input value to a INT value: 饱和度, , invalid literal for int() with base 10: ''
```

**原因**：ComfyUI 在真正执行节点之前，会先在 `execution.py` 里做类型校验：
`INT` 走 `int(val)`、`FLOAT` 走 `float(val)`。只要前端送来的是**空字符串**，
这一步就抛异常，整个 prompt 直接判为非法，**节点代码根本还没开始跑**。
空字符串来自**旧版本存的工作流**：图片调整节点最早只有 5 个参数，后来扩到 12 个，现在 13 个。

**处理（已内置三层兜底，无需手动操作）**

| 时机 | 行为 |
|---|---|
| 加载工作流（`onConfigure`） | 检测到 `widgets_values` 比当前参数少 → 整组重置为默认值，并打印一行警告 |
| 节点创建 / 单个值为空 | 只把空掉的那几个参数回填默认值，其余不动 |
| 提交前（拦截 `graphToPrompt`） | 逐个数字参数体检：空串、`null`、`NaN`、非数字字符串 → 换默认值；`"11"` 这种字符串数字 → 转真数字。**模型名和连线不动** |

后端节点内部也做了同样的容错（`float("")` / `int("")` 一律回落默认），保证 API 直接调用不会炸。

**建议**：旧工作流里的参数是**按位置错位**存进去的（旧的「色温」会落到新的「鲜明度」上），
兜底只能保证能跑，值对不对没法替你判断。**最干净的做法是把节点删掉重新拖一个。**

## 已知限制

- `auto_link` 自动发现模式下，一个 loader 会同时连接画布上**所有**符合条件的节点；
  如需只连某一个，请用右键菜单「指定多图目标」锁定
- Node 2.0 下界面是 DOM 版：拖拽排序**没有**原来那种实时让位动画，松手即换位；
  悬停高亮、尺寸标注等其余信息都在
- 音频波形要等浏览器解码完才出现（大文件约 1 秒），解码前只显示空白波形区，裁剪竖线也要等它
- 小脸涂抹只涂**脸框范围**（放大 1.8 倍），不会把整个小人抹掉；
  如果素材里小脸的身体也干扰构图，需要另外做语义抠图

## 变更记录

- **修复**：多图 / 多音频载入「**切到别的工作流再切回来就乱连线**」（本来是对的，什么都没动就变乱）。
  切标签页会走 `loadGraphData` 重建整张图，重建时本节点的 `onConfigure` 先跑，
  而对端节点还没 configure 完、存档连线也还没恢复，此时建链 -> 前端随后再把存档的线恢复一遍
   -> 同一个槽两条线。现在载入期一律不建链，载入结束再收口：
  按「输出序号 = 槽位序号」清掉错位 / 孤儿 / 悬空连线，再补齐缺的槽，连跑四轮
- **新增**：控制台排查命令 `__tyAuditImageLinks()`（打印多图载入的全部连线，标出错位行）
- **修复**：多图 / 多音频载入「重开工作流连线错位」—— 一个输入槽上叠出多条残留连线
  （孤儿），重开时全部画在第一个槽上。改为不自己造 autogrow 槽位、不再产生孤儿，
  并在每次同步时清理已有脏连线
- **文档**：补上整合包（模型 + 工作流）地址 <https://pan.quark.cn/s/bc37598df71d>
- **移除**：`面部去高光（只取肤色）` 节点从节点列表删除（算法模块 `face_dehighlight.py` 保留，
  供「重绘·保纹理」复用）。旧工作流里如果还留着这个节点，加载后会显示为缺失节点
- **改名**：`Multi Image Loader` → **多图载入**，`Multi Audio Loader` → **多音频载入**
  （只改显示名，`class_type` 没变，旧工作流照常加载）
- **新增**：`小脸涂抹（去参考图杂脸）`
